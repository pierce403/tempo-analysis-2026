# Curator

Keep the skill library small, evidence-backed, and useful for future Tempo research.

## Workflow

1. Review the completed task's evidence, dated log, user corrections, successes, failures, and remaining uncertainty.
2. Generalize only lessons that apply beyond the single run. Keep facts in memory, repository-wide rules in `AGENTS.md`, and procedures in skills.
3. Search `SKILLS.md` and `skills/` before creating anything. Update an existing class-level skill when it already owns the workflow.
4. Require an `active` learning, repeated need, or explicit user request before creating a new skill. A new skill needs a discriminating trigger and a stable, reusable procedure.
5. Keep instructions concise. Add scripts only for repeated deterministic work and references only for conditional detail that changes decisions.
6. Validate new or substantially changed skills with the system skill validator, inspect for scaffold placeholders, and run any added scripts.
7. Update `SKILLS.md`, retire promoted learning entries with a destination link, and record the change in the dated work log.

## Boundaries

- Do not promote unverified conclusions, candidate vulnerabilities, secrets, personal data, or one-off workarounds.
- Do not let a skill silently expand authorization for active testing, disclosure, deployment, commits, or external writes.
- Do not recursively edit this skill, `AGENTS.md` safety boundaries, or the improvement trust chain without explicit user direction.
- Prefer reversible changes and preserve evidence for why a rule was promoted.

## Done criteria

- The destination is appropriate: log, memory, decision, project rule, or skill.
- No existing skill should own the same procedure more clearly.
- Catalog, learning state, and dated log agree.
- Validation passes and no placeholder guidance remains.
