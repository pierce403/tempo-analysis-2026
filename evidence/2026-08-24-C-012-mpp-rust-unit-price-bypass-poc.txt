LOSS BOUND

For advertised per-response price P and accepted increment d, unpaid value per
response is P-d. In the bundled example P=10000 and the smallest accepted
positive d=1, producing 9999 units (99.99%) underpayment per response. The
pattern can repeat with successively higher valid vouchers, subject to deposit
headroom, concurrency/rate limits, top-up, and application controls.

AFFECTED AND UNDEMONSTRATED PATTERNS

Confirmed:
  - bundled multi-fetch example at current head and published v0.11.0;
  - verification-only request/response handlers with min delta below cost;
  - variable-price handlers that rely on one static min delta instead of an
    atomic debit of the authenticated per-request cost.

Not shown affected:
  - bundled SSE and WebSocket paths, which atomically debit per event/frame;
  - applications that atomically require available authorization and persist
    spent += request cost before delivery;
  - current TypeScript integrations, which require separate reproduction.

SPECIFICATION AND PRIOR ART

The pinned Tempo session draft says amount is price per unit and requires each
paid request to compute cost, check acceptedCumulative-spent, and persist
spent += cost before or atomically with delivery. minVoucherDelta is a server
policy/anti-flood threshold, not the authenticated resource charge.

The example pattern dates to commit
acf42ea5887b979d3dcd68d8c4cf9b054622b69d. Public security commit
d95c787835559e25b25b46fa9e262f33fb1c88cd / GHSA-fxc9-7j2w-vx54 and replay
fix 3b167f47ef2019f4b6b407828b31d1d9acda57d3 did not add a per-request price
debit. Private awareness and production adoption remain unknown.

REMEDIATION

Use one linearizable request-payment operation that persists a higher voucher
if needed, derives a server-owned route cost, requires sufficient unspent
authorization, increments spent by that cost, and only then permits delivery.
Keep minVoucherDelta as an independent anti-flood control. Update the bundled
example and add tests where challenge price exceeds the presented voucher
increment.
