LOSS BOUND

For N requests that reach validation against the same old snapshot, up to N
protected responses can satisfy the delivery predicate while voucher value
advances by one accepted increment delta. If each response has value P,
uncompensated exposure is:

  max(0, N * P - delta)

When delta correctly prices one response (delta = P), race-only duplicate loss
is (N - 1) * P.

N is limited by server concurrency and timing. The pattern can repeat with
successive higher vouchers. No signature forgery or victim payer key is needed;
the dishonest payer needs its own funded channel and signer.

AFFECTED AND UNDEMONSTRATED PATTERNS

Confirmed:
  - bundled multi-fetch delivery pattern at current head and v0.11.0;
  - applications that treat verify_session success as authorization for one
    paid response without atomically debiting per-request spent;
  - in-memory and single-process adapter stores. Correct update serialization
    does not reject the losing request.

Not shown affected by this specific duplicate-delivery path:
  - bundled SSE, which atomically deducts before each event;
  - bundled WebSocket session serving, which deducts before each data frame;
  - applications that perform a linearizable per-request debit before delivery.

SPECIFICATION CONFLICT

mpp-specs draft-tempo-session-00.md requires per-channel voucher acceptance and
balance deduction to be serialized, accounting updates to be linearizable, and
spent to be persisted before or atomically with delivery. Exact management
voucher retries can be idempotent, but a replay/no-op must not be mistaken for
fresh authorization to deliver another paid resource.

REMEDIATION PROPERTY

Combine voucher advancement, request-cost balance validation, and spent debit
in one linearizable transition. Only its winner may cross the paid-delivery
gate. Return a distinguishable replay/CAS-loss result to other requests, while
preserving management-only idempotency separately.

No public endpoint, payment, production server, credential, or third-party
service was tested. The exact local patch remains in the ignored findings
directory.
