## T-013 — Report claim-to-evidence traceability

- **User requirement**: Every claim in `REPORT.md` must link directly to evidence visible in the repository, and that evidence must be a timestamped command or another deterministic procedure that a reviewer can rerun.
- **Initial state**: The 608-line report had 49 direct `evidence/` links. Findings had section-level evidence pointers, but most executive, surface, compound-path, limitation, and remediation claim blocks did not link directly. Several evidence commands referenced ignored `target/` or `findings/` PoCs unavailable from a fresh clone.
- **Plan**: Define claim units, commit sanitized reproduction fixtures, normalize evidence provenance and rerun instructions, add direct links to every claim unit, add a deterministic verifier, then validate and publish only to `origin/main`.
- **Safety boundary**: Public source, already captured passive observations, and local dummy/in-memory reproduction only. No credential use, workflow trigger, live payment, transaction, authentication test, production mutation, or unrelated third-party testing.
- **Result**: `REPORT.md` version 1.2 contains 309 claim units—54 metadata lines, 87 prose paragraphs, 95 list items, and 73 table rows—and all 309 link directly to one or more of 19 repository evidence artifacts. The linked narrative artifacts satisfy the dated-provenance, safe-rerun, captured-result, and limitation contract.
- **Reproducibility**: Added `evidence/README.md`, `scripts/verify_report_evidence.py`, a safe full-history TruffleHog wrapper, and committed sanitized fixtures for C-002 through C-012 where local reproduction or control modeling applies. Fresh disposable-clone checks reproduced the focused contract, wallet, workflow, and MPP results; the pinned full Rust MPP suite remained green with 1,160 library tests, 16 integration tests, and 61 executed doctests.
- **Quality gates**: Reconciled 12 findings as P0=2, P1=5, P2=4, and P3=1; exactly 10 evidence-type records describe executed PoCs, C-006 has a separate local release-control model, C-001 retains a historical read-only timeline, and two secret-hygiene observations remain owner-confirmation items. A final non-verifying TruffleHog filesystem scan found only three immutable Git-SHA false positives and one intentional dummy-token URI; no real credential candidate was retained.
- **Review lesson**: Structural link coverage is necessary but not sufficient. A final semantic audit caught mutable date language, links that supported only part of a compound claim, stale fixture hashes, and commands that assumed an ignored checkout. Future report changes should run both the automated gate and a claim-to-artifact semantic review before publication.
